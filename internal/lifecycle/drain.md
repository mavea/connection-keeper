# Менеджер дренажа

`internal/lifecycle/drain.go` реализует `domain.DrainManager`.

## Назначение

Менеджер дренажа отслеживает старые поколения коннекторов и гарантирует, что для каждого зарегистрированного поколения будет вызван финальный callback дренажа перед завершением процесса.

Используется в двух местах:

- `manager/manager.go`:
  - `DrainNext()` вызывается в основном цикле `Run()`;
  - `DrainAll()` вызывается во время `Shutdown()`.
- `internal/connector/{input,output}.go`:
  - старые поколения регистрируются через `Register(gen, closeFn)` после handover.

## Поведение

- `Register(gen, closeFn)` добавляет поколение во внутреннюю очередь.
- `DrainNext()` обрабатывает одно поколение из очереди по кругу:
  - если `gen.WaitForClose()` уже закрыт, сразу вызывается `closeFn`, после чего поколение удаляется из очереди;
  - иначе выполняется ожидание до `Config.CancelWaitTimeOut()`;
  - при таймауте увеличивается счётчик попыток;
  - когда число попыток достигает `Config.MaxRetryWaitAttempts()`, вызывается `closeFn`, после чего поколение удаляется.
- `DrainAll()` вызывает `DrainNext()` до тех пор, пока очередь не опустеет, и возвращает объединённую ошибку из всех callback дренажа.

## Примечания

- Внутри реализации нет синхронизации; предполагается вызов из одного управляющего потоком менеджера. Соответственно система не потокобезопасна.
- `closeFn` может быть `nil`; в этом случае он трактуется как noop.
