# Registry менеджер

`internal/lifecycle/registry.go` реализует `domain.RegistryManager` и хранит актуальные поколения коннекторов.

## Цель

`registry` сделан для быстрого доступа по индексу `kind.ID()`:

- чтение поколения выполняется без блокировок;
- запись нового поколения выполняется атомарной публикацией пары значений;
- расширение массива слотов выполняется только во время регистрации kind.

## Ключевые структуры

- `registry` — массив слотов `slots []*registrySlot` и `mu sync.Mutex` для безопасного расширения массива при регистрации.
- `registrySlot` — атомарный контейнер для одной актуальной пары.
- `registryValue` — неизменяемая пара:
  - `generation domain.GenerationAny`
  - `close any`

## Как это работает

1. `RegisterGeneration(kind)`:
   - по `kind.ID()` расширяет `slots` до нужного индекса;
   - инициализирует отсутствующие элементы через `newRegistrySlot()`;
   - защищён `mu`, чтобы несколько регистраций не ломали массив.
2. `SetGeneration(kind, generation, close)`:
   - берёт уже зарегистрированный слот;
   - вызывает `slot.store(...)`, который атомарно публикует новую пару.
3. `GetGeneration(kind)` и `GetGenerationAndCancelFunc(kind)`:
   - читают слот через `slot.load()`;
   - получают согласованное состояние пары без локов.

## Методы `registrySlot`

- `newRegistrySlot()`
  - создаёт слот и записывает в него пустой `registryValue`;
  - гарантирует, что `load()` можно вызывать сразу после регистрации.
- `store(generation, close)`
  - создаёт новый `registryValue`;
  - атомарно публикует его через `atomic.Pointer.Store`.
- `load()`
  - атомарно читает текущее значение `registryValue`;
  - возвращает `nil`, если слот не задан.

## Договорённости

- `kind.ID()` по контракту `domain.Kind` всегда положительный.
- `SetGeneration` вызывается только после `RegisterGeneration` для того же `kind`.
- Компонент внутренний, внешние прямые вызовы не предполагаются.

## Что это даёт

- Быстрый hot-path для чтений.
- Отсутствие гонки «старое поколение + новый callback».
- Минимальная синхронизация: mutex только на этапе регистрации слотов.
