# Connector менеджер

`internal/lifecycle/connector.go` реализует `domain.ConnectorManager` и хранит коннекторы, которые используются для
создания и обновления поколений.

## Назначение

- быстрый доступ к коннектору по `kind.ID()`;
- поддержка многопоточной регистрации коннекторов;
- быстрый путь чтения без локов.

## Модель конкурентности

- `RegisterConnector(kind, con)` потокобезопасен:
  - использует `mu sync.Mutex`;
  - безопасно расширяет внутренний слайс;
  - гарантирует, что для одного `kind` будет зарегистрирован только один коннектор.

- `GetConnector(kind)` выполняется без блокировок:
  - рассчитан на single-thread сценарий чтения;
  - не потокобезопасен при одновременной записи;
  - не должен вызываться конкурентно с `RegisterConnector`, иначе возможна data race.

## Алгоритм

1. Регистрация:
   - по `kind.ID()` расширяется слайс `connectors`;
   - если слот уже занят, возвращается `ErrFabricAlreadyRegistered`;
   - иначе коннектор сохраняется в слот.
2. Чтение:
   - проверяется, что индекс есть в слайсе;
   - проверяется, что в слоте не `nil`;
   - возвращается коннектор или `ErrFabricConstructorNotFound`.

## Договорённости

- `kind.ID()` по контракту `domain.Kind` всегда положительный.
- Внешние вызовы вне библиотеки не предполагаются.
- Приоритет этой структуры — скорость чтения в рабочем цикле менеджера.
